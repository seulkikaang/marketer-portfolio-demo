## 0. 딥리서치 요약 — 젠스파크 AgentBase, 지금 뭐가 되는가

### 확인된 사실 (2026년 7월 기준)

- **AgentBase는 2026년 6월 퍼블릭 프리뷰로 출시**된 젠스파크의 신기능. 이메일·드라이브·파일·기존 DB에 흩어진 데이터를 **커스텀 데이터베이스 + 대시보드 + 사내 시스템(CRM, HR, 프로젝트 트래커, 재고 관리 등)** 으로 자연어만으로 변환해 주는 "내부 소프트웨어 빌더"다.
- **템플릿**이 준비되어 있어 빠르게 시작 가능하고, 리스트·상세·폼·대시보드 같은 UI 패턴과 백엔드 스키마를 한 번에 생성한다.
- 구조화된 데이터 위에서 **Super Agent가 이메일 초안, 리서치, 대시보드 생성, 워크플로우 설정**까지 이어서 처리한다.
- **30개 이상 업무 도구 연동**: Google Workspace(Gmail 포함), Outlook, Notion, Salesforce, HubSpot 등.
- 주변 기능: **AI Sheets**(웹에서 데이터 수집→라이브 테이블→차트 자동 생성), **AI Developer**(풀스택 웹앱 자동 개발, 공개 링크 배포), **워크플로우 자동화/예약 실행**, Speakly(음성 조작).
- 과금은 **크레딧 기반**. 무료는 일 ~100크레딧 수준이라 데모·리허설용으로는 유료 플랜(월 $24.99~) 필수. 한 번의 시연 플로우가 크레딧을 여러 번 소모한다.

### 아직 불확실한 것 (→ 데모 계정 받으면 첫날 검증할 것)

| 항목 | 리스크 | 검증 방법 |
|---|---|---|
| 비로그인 방문자용 **공개 폼/공개 링크** 제공 여부 | 태블릿 입력 장면 설계가 달라짐 | 데모 계정에서 폼 생성 후 시크릿창 접속 테스트 |
| 워크플로우 **실행 과정(4단계)이 화면에 단계별로 보이는지** | "파이프라인 시연" 연출 가능 여부 | 테스트 워크플로우 만들어 실행 화면 녹화 |
| 외부 SNS 채널 **실시간 크롤링 성공률/소요 시간** | 라이브 시연 중 1~3분 침묵 발생 가능 | 가상 채널 대신 실제 공개 채널 3개로 시간 측정 |
| 시스템 **템플릿 복제 공유**(이메일로 "그대로 가져가기") 방식 | 마지막 장면(이메일 캡처→시스템 전달) 구현 방식 | 템플릿 공유 링크 발급 테스트 |

**핵심 결론: 요청하신 시나리오는 AgentBase + Super Agent 워크플로우 조합으로 구현 가능하다. 단, "라이브로 도는 것"과 "사전 준비해 두는 것"을 정확히 나누는 게 이번 플랜의 전부다.** 라이브 실패 가능성이 있는 모든 지점에 사전 캐시 데이터(플랜 B)를 깔아 둔다.

## 1. 전체 구성 제안

행사에서 3개 실현 예정이라고 하셨으니 아래 구성을 추천한다.

| # | 데모 | 역할 | 구현 도구 | 공수 |
|---|---|---|---|---|
| 1 | **트렌드 레이더 시스템** (핵심) | 메인 무대. 관객 참여 + 리드 수집 | AgentBase(DB/대시보드/폼) + Super Agent(워크플로우) | 1.5일 |
| 2 | **1인 크리에이터 수출입 정리 시스템** | "이런 것도 됩니다" 서브 데모 | AgentBase 단독 (CSV 업로드 → 시스템 생성) | 0.5일 |
| 3 | **인플루언서 협업 일정 관리 시스템** | 서브 데모 (2와 택일하거나 둘 다) | AgentBase 단독 | 0.5일 |
| 옵션 | 여행 플래너 (디자인+애니메이션) | 비주얼 임팩트용 | **AI Developer**로 별도 웹앱 (AgentBase 아님) | 0.5~1일 |

여행 플래너는 "디자인+애니메이션"이 요구사항이라 AgentBase(업무 시스템 UI)보다 **AI Developer로 만든 공개 웹앱**이 맞다. 일정이 빠듯하니 1~3을 먼저 확정하고, 여행 플래너는 화요일 오전에 여유 있을 때만.

이 저장소 `agentbase-demo/data/`에 **바로 업로드 가능한 페이크 데이터 7종**을 만들어 뒀다(상세: §5). 모든 채널명·브랜드명은 가상이다 — 행사에서 실존 크리에이터 실명/채널을 쓰면 초상권·명예 이슈가 생길 수 있어 일부러 가상으로 설계했다. 현장 참여자가 자기 채널을 직접 넣는 것은 본인 동의라 문제없다.

## 2. 데모 1 — 트렌드 레이더 시스템 (장면별 구현)

### 시스템 구조

```
[트렌드 DB]  ←(매일 예약 워크플로우: 트렌드 수집·갱신)
     │
[자동 정렬 대시보드]  ← 성장률/플랫폼/카테고리별 뷰
     │
[방문자 입력(채널 링크)] → [4단계 파이프라인 워크플로우] → [맞춤 추천 출력]
     │
[이메일 입력] → [리드 테이블 저장 + 추천 리포트/시스템 템플릿 메일 발송]
```

AgentBase 안에 테이블 3개를 만든다: **① 트렌드 DB ② 방문자 리드 ③ 추천 결과**. 빌드는 코딩이 아니라 자연어 프롬프트 + CSV 업로드로 한다 (복붙용 프롬프트: `PROMPTS.md`).

### 장면 1. 시스템 구경 (대형 화면)

- 대형 화면에는 **대시보드 뷰를 전체화면**으로 미리 띄워 둔다. 트렌드 40건이 성장률 순으로 정렬되고, 플랫폼별 분포 차트가 보이는 상태.
- 연출 팁: 화면보호기/절전 끄기, 브라우저 북마크바 숨기기, 탭 하나만. "이미 돌아가고 있는 시스템"이라는 인상은 **마지막 갱신 시각 필드**("오늘 06:00 자동 갱신됨")가 만들어 준다 — 트렌드 DB에 `수집일` 컬럼을 넣어 둔 이유.

### 장면 2. 트렌드 DB → 대시보드 ⭐️ (핵심 장면)

- 시연 순서: 테이블(표) 뷰를 먼저 보여주고 → "이걸 대시보드로 바꿔줘" 한 마디로 뷰 전환 → 자동 정렬·차트 생성되는 과정을 보여준다.
- **현실적인 방법**: 대시보드는 사전에 이미 만들어 두고, 무대에서는 "정렬 기준을 7일 성장률로 바꿔줘" / "플랫폼별로 묶어줘" 같은 **가벼운 변형 명령**을 라이브로 친다. 제로부터 대시보드 생성은 수십 초~수 분 걸릴 수 있고 결과 레이아웃이 매번 달라서 무대 리스크가 크다. 가벼운 변형은 빠르고 안정적이면서 "말로 시스템이 바뀐다"는 임팩트는 동일하다.
- 리허설 때 **정확히 같은 문장**으로 3회 이상 돌려서 출력이 안정적인 문장만 대본에 넣는다.

### 장면 3. 채널 링크 → 4단계 워크플로우 (관객 참여)

- 태블릿은 **데모 계정으로 로그인된 상태**로 폼(또는 리드 테이블의 새 레코드 입력 화면)을 띄워 둔다. 공개 폼이 지원되면 그걸 쓰고(§0 검증 항목), 안 되면 로그인된 태블릿 자체가 입력 키오스크가 된다 — 방문자 경험은 동일하다.
- 입력 필드는 **채널 링크 + 플랫폼 선택** 딱 2개. 현장에서는 필드가 많을수록 이탈한다.
- 레코드가 추가되면 4단계 파이프라인 워크플로우 실행: **채널 데이터 수집 → 채널 성격 파악 → 트렌드 DB 대조 → 맞춤 추천 3건 생성** (추천 결과 테이블에 기록 + 화면 출력).
- **소요 시간이 최대 리스크다.** 실제 채널 크롤링+분석은 1~5분 걸릴 수 있다. 무대 운영은 이렇게:
  - **라이브 1건만**: 사회자가 미리 섭외한 방문자(또는 스태프) 채널 1건을 라이브로 돌리고, 도는 동안 사회자가 파이프라인 단계 화면을 해설한다. "기다림"을 "단계별 시연"으로 바꾸는 것.
  - 부스 상시 운영분은 "추천은 이메일로 보내드려요"로 비동기 전환 — 오히려 이메일 수집(장면 5)과 자연스럽게 연결된다.
  - **플랜 B**: 크롤링이 실패하면 사전 캐시로 전환. `channel_profiles.csv`(가상 채널 5개)와 `matched_recommendations.csv`(채널별 추천 3건 + 추천 이유 + 첫 3초 훅 아이디어)가 이미 테이블에 들어 있으므로, "예시 채널로 보여드릴게요" 하고 캐시된 결과를 연다. 관객은 차이를 모른다.

### 장면 4. 자동 갱신 + 즉석 수정

- **매일 자동 갱신**: 예약 워크플로우("매일 06:00 틱톡·릴스·쇼츠 트렌드 리서치 → 트렌드 DB에 신규 행 추가, 성장률 갱신")를 실제로 걸어 둔다. 무대에서는 스케줄 설정 화면을 보여주고, **수동 실행 버튼으로 즉시 1회 트리거**해서 새 행이 추가되는 걸 보여준다. "매일 새벽에 이게 돌아갑니다"라는 멘트와 함께.
- **"쇼츠만 보여줘"**: 자연어 필터 명령. 이건 뷰 필터 변경이라 빠르고 안정적 — 즉석 수정 시연으로 최적. 여기도 리허설에서 확정한 문장 그대로.

### 장면 5. 이메일 (리드 캡처 + 시스템 전달)

- 태블릿 폼에 이메일 입력 → 리드 테이블 저장 → Gmail 연동 워크플로우가 **① 맞춤 추천 리포트 ② 시스템 템플릿 링크**("이 시스템을 그대로 복제해서 쓰세요")를 발송.
- 템플릿 공유 링크 발급이 안 되는 경우(§0 검증): 젠스파크 가입 안내 + 빌드 프롬프트 전문(`PROMPTS.md` 내용)을 메일에 담아 보낸다 — "이 프롬프트 한 번이면 같은 시스템이 만들어집니다"도 충분히 강력한 CTA다.
- 발송 메일 주소는 데모용 계정으로. 회사 실계정 Gmail을 물리면 오발송 리스크가 있다.

## 3. 데모 2·3 — 수출입 정리 / 협업 일정 관리

두 데모는 같은 패턴이다: **CSV 업로드 → "이 데이터로 시스템 만들어줘" → 3분 만에 업무 시스템 완성**. 트렌드 레이더가 "정교하게 짜인 시스템"을 보여준다면, 이 둘은 "여러분 데이터로도 즉시 됩니다"를 보여주는 역할.

### 데모 2. 1인 크리에이터 수출입 정리 시스템

- 데이터: `creator_trade_ledger.csv` (40건 — 사입/굿즈 수출, 통화 5종, 관세·통관·정산 상태 포함).
- 만들 뷰: ① 전체 거래 대장 ② 수입/수출 구분 보드 ③ **월별 손익 대시보드**(원화 환산 합계) ④ "통관 대기 + 정산 미완료" 알림 뷰.
- 시연 킬러 멘트: "관세 납부 대기인 건만 보여줘" → 필터 즉시 적용. "이번 달 수출 매출 원화로 합쳐줘" → 집계.
- 자동화 1개만: "배송 상태가 통관 대기로 7일 이상이면 알림" — 설정 화면만 보여줘도 충분.

### 데모 3. 인플루언서 협업 프로젝트 일정 관리

- 데이터: `influencer_collab_projects.csv`(캠페인 12건) + `collab_tasks.csv`(태스크 24건) — 컨택→계약→초안→피드백→업로드→정산 8단계 파이프라인.
- 만들 뷰: ① 단계별 칸반 보드 ② 마감일 캘린더/타임라인 ③ 인플루언서별 그룹 뷰 ④ "지연" 상태 필터.
- 시연 킬러 멘트: "이번 주 마감인데 아직 초안 안 온 프로젝트 알려줘" / "지연된 건 담당 매니저한테 리마인드 메일 초안 써줘" (Super Agent 연계 — 리허설 필수).

### 옵션. 여행 플래너 (AI Developer)

- AgentBase가 아니라 **AI Developer에게 원샷 프롬프트**로 만들고 공개 링크로 배포: "3박 4일 제주 여행 플래너 웹앱. 날짜별 타임라인, 지도 느낌의 카드 레이아웃, 부드러운 스크롤 애니메이션과 마이크로 인터랙션, 모바일 대응." 생성물 QA(깨진 부분 수정 요청 1~2회) 시간까지 반나절 잡을 것.
- 행사 스토리상 역할: "업무 시스템(AgentBase)뿐 아니라 비주얼 결과물(AI Developer)까지, 젠스파크 하나로" 라는 마무리 카드.

| **화 오후** | 전 장면 통합 리허설 1회 → 시연 대본(정확한 명령 문장 포함) 작성 → **납품**: 계정 세팅 완료 상태 + 대본 + 이 문서 |
| **수** | 발표자 교육 — 대본의 명령 문장을 그대로 치는 연습. 애드리브 명령 금지 원칙 공유 |
| **목** | 현장 리허설 — 행사장 와이파이로 전 플로우 실측(§6 체크리스트), 실패 지점은 즉시 플랜 B로 대본 수정 |
| **금** | 행사 🎉 |

## 6. 리허설 체크리스트 & 리스크

### 목요일 현장 체크리스트

- [ ] 행사장 와이파이에서 젠스파크 접속·로그인 (모바일 핫스팟 백업 준비)
- [ ] 대형 화면: 대시보드 전체화면, 알림·절전·브라우저 UI 정리
- [ ] 태블릿: 폼 화면 고정, 자동잠금 해제, 충전기
- [ ] 라이브 채널 분석 1건 실측 (소요 시간 스톱워치) — 3분 초과 시 대본에서 비동기 전환
- [ ] "쇼츠만 보여줘" 등 대본 명령 문장 전부 1회씩 실행
- [ ] 수동 갱신 트리거 → 새 행 추가 확인
- [ ] 테스트 이메일 발송 → 수신함 확인 (스팸함 포함)
- [ ] 크레딧 잔량 확인 — **리허설+행사에서 같은 플로우를 10회 이상 돌린다고 가정**하고 여유분 확보
- [ ] 플랜 B 진입 동선 연습: 캐시된 예시 채널 여는 데 10초 이내

### 리스크 매트릭스

| 리스크 | 확률 | 대응 |
|---|---|---|
| 라이브 채널 크롤링 실패/지연 | 중~높음 | 사전 캐시 5채널 + "예시 채널" 전환 대본 |
| 현장 네트워크 불안정 | 중 | 핫스팟 백업 + 핵심 장면 **스크린 녹화본** 노트북에 저장 (최후의 보루) |
| 자연어 명령이 리허설과 다른 결과 출력 | 중 | 대본 문장 고정, 애드리브 금지, 뷰는 사전 저장본으로 즉시 복구 |
| 크레딧 소진 | 중 | 유료 플랜 + 행사 전날 잔량 확인 |
| 공개 폼/템플릿 공유 미지원 | 중 | 로그인 태블릿 키오스크化 + 프롬프트 전문 메일 발송으로 대체 (§2 장면 3·5) |
| 방문자가 비공개/신생 채널 입력 | 높음 | 폼 안내 문구: "공개 채널 링크를 입력해 주세요" + 분석 불가 시 캐시 채널로 안내 |
