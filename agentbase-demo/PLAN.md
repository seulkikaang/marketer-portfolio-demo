### 데모 설계를 바꾸는 3가지 교정

1. **"폼 제출 → 자동 파이프라인 실행"은 불가능하다 (❌ #7).** 무대에서 "제출 즉시 자동으로 돌아갑니다"라고 말하면 허위 시연이 된다. 대신 두 경로로 재설계:
   - **무대(라이브)**: 폼 제출 → 레코드가 테이블에 꽂히고 **대시보드가 데이터 변경에 맞춰 자동 갱신**(공식 확인됨) → 사회자가 Super Agent 채팅에 "방금 접수된 채널 분석해줘"라고 지시 → 4단계 실행 과정이 화면에 표시. "사람이 버튼을 누르는" 게 아니라 "에이전트에게 말로 시키는" 연출이라 오히려 자연스럽다.
   - **상시(부스 운영)**: 30분 간격 스케줄 워크플로우가 리드 테이블에서 "발송 상태=대기"인 레코드만 골라 배치 처리(분석→추천 저장→이메일 발송→상태를 '완료'로 갱신). 상태 컬럼이 중복 발송 방지 장치다 — 페이크 데이터에 이미 반영해 뒀다.
2. **공개 폼은 확실히 된다 (✅ #6).** 비로그인 제출 + 필드 숨김까지 공식 지원. 태블릿을 로그인 키오스크로 쓸 필요가 없고, **QR 포스터로 방문자 자기 폰 입력**까지 확장 가능(병목 해소 + 행사 후에도 같은 URL로 리드 유입).
3. **"시스템을 그대로 가져가세요"는 표현을 바꿔야 한다 (⚠️ #12).** 시스템 통째 복제 링크는 근거 없음. 대체: ① 4단계 파이프라인을 **커스텀 슈퍼 에이전트**로 패키징해 공유 링크 발송(공유 링크·비계정 사용 사례 확인됨 — 단 화요일 실검증 필요), ② 빌드 프롬프트 레시피 전문을 메일로 발송("이 프롬프트 한 번이면 같은 시스템"). 무대 멘트는 "추천 리포트 + 이 시스템을 만드는 레시피(또는 진단 에이전트 링크)를 보내드립니다"로.

## 1. 전체 구성

| # | 데모 | 역할 | 구현 도구 | 공수 |
|---|---|---|---|---|
| 1 | **트렌드 레이더 시스템** (핵심) | 메인 무대. 관객 참여 + 리드 수집 | AgentBase(DB/대시보드/공개 폼) + Super Agent(채팅 파이프라인) + 스케줄 워크플로우 | 1.5일 |
| 2 | **1인 크리에이터 수출입 정리 시스템** | "3분 라이브 빌드" 쇼 | AgentBase (CSV 업로드 + 자연어) | 0.5일 |
| 3 | **인플루언서 협업 일정 관리** | 뷰 전환·자연어 조작 시연 | AgentBase | 0.5일 |
| 옵션 | 여행 플래너 (디자인+애니메이션) | 비주얼 마무리 | **AI Developer** (공개 URL 배포 ✅ 검증됨) | 0.5~1일 |

AgentBase 구조는 3계층(Tables → Views&Dashboards → Workflows)이고, 실제 관리형 PostgreSQL 위 관계형 테이블 + 일일 자동 백업 + 영구 워크스페이스다 — "노코드 장난감이 아니라 진짜 DB"라는 무대 멘트가 사실로 뒷받침된다. 주의: **한 대화당 시스템 1개**(두 번째 시스템은 홈으로 나가서 새로), 생성 전 AI가 확인 질문 몇 개를 먼저 던진다(소요시간에 포함).

준비 필수 시청 자료: 공식 46분 워크스루 [Genspark Academy: Learn All About AgentBase](https://www.youtube.com/watch?v=PiiT3lzfR-k) (CSV 업로드→템플릿→베이스→뷰→대시보드→워크플로우 전 과정), 공식 한국어 런칭 영상 [젠스파크 코리아](https://www.youtube.com/watch?v=hJc5TL0FhL8) (1분 52초 — 무대 오프닝 상영용으로도 활용 가능).

## 2. 데모 1 — 트렌드 레이더 시스템 (장면별, 검증 반영)

### 시스템 구조

```
[트렌드 DB]  ←(스케줄 워크플로우: 매일 06:00 KST 트렌드 리서치·갱신)
     │
[자동 정렬 대시보드]  ← 데이터 변경 시 자동 갱신 (공식 확인)
     │
[공개 폼(비로그인)] → 리드 테이블에 레코드 생성
     │                    ├─ 무대: Super Agent 채팅 지시로 4단계 파이프라인 라이브 실행
     │                    └─ 상시: 30분 간격 워크플로우가 '대기' 레코드 배치 처리
[추천 결과 테이블] → Gmail 발송 (추천 리포트 + 레시피/에이전트 링크)
```

### 장면 1. 시스템 구경 (대형 화면)

- 대시보드 전체화면 + `수집일` 필드("오늘 06:00 갱신"). 추가 연출: **My Workflows 실행 이력 패널**(각 실행의 상태·트리거 시각·소요 시간이 기록됨 — 공식 확인)을 잠깐 보여주면 "매일 실제로 돌고 있다"의 증거가 된다.
- 대형 화면은 로그인된 발표 노트북으로 띄운다. **비로그인 공개 대시보드 링크는 미확인**이므로 계획에 넣지 않는다.

### 장면 2. 트렌드 DB → 대시보드 ⭐️ (핵심 장면)

- 순서: 테이블 뷰 → **뷰 전환 원클릭**(Table→Kanban→Calendar, 즉각 반응·크레딧 무료) → 대시보드.
- 즉석 수정은 **두 속도를 구분해서 연출**한다:
  - **0초 반응이 필요할 때**: 대시보드 차트 요소 **클릭 → 하위 테이블 필터**(공식 지원). "플랫폼 차트에서 쇼츠 조각을 클릭하면 아래 표가 쇼츠만 남습니다."
  - **"말로 바꾸는" 임팩트가 필요할 때**: 공식 시연에서 검증된 명령 패턴 그대로 — "막대 차트를 퍼널로 바꿔줘", "쇼츠만 보여줘". 에이전트가 5단계(Thinking→…→Verifying)를 돌므로 **수십 초 걸린다** — 사회자가 그 과정 자체를 해설한다("지금 AI가 어떤 차트가 적합한지 검증 중입니다").
- 제로부터 대시보드 생성은 무대에서 하지 않는다(수 분 + 비결정적). 사전 생성본에 가벼운 수정만.

### 장면 3. 채널 링크 → 파이프라인 (관객 참여, 재설계됨)

- **입력**: 공개 폼 링크(비로그인 ✅)를 태블릿에 띄우고, 같은 링크의 **QR 포스터**를 부스에 세운다. 방문자는 자기 폰으로도 참여 — 태블릿 병목 해소, 행사 후에도 URL이 살아 리드가 계속 들어온다.
- 폼 필드: 채널 링크(필수) / 플랫폼(선택) / 이메일(선택) / **개인정보 수집·이용 동의(필수)**. 이메일을 해외 사업자(Genspark) 서버에 저장하게 되므로 **수집 목적·보유 기간·국외 이전 고지 문구가 법적으로 필요**하다(개인정보보호법). 폼에 체크박스 필드가 안 되면 안내 문구+제출로 갈음하되 화요일에 반드시 확인.
- **무대 라이브 연출 (이중 화면)**: 방문자가 폼 제출 → 대형 화면의 리드 테이블에 레코드가 꽂히고 대시보드 카운트가 자동 갱신 → 사회자가 Super Agent 채팅에 **"방금 접수된 채널을 분석해서 맞춤 트렌드 3개를 추천해줘"** → 에이전트의 4단계 실행 과정(채널 수집→성격 파악→DB 대조→추천 생성)이 그대로 노출되고 사회자가 스포츠 중계식 해설. 기다림이 콘텐츠가 된다.
- **플랫폼별 성공률이 다르다 — 대본에 반영**:
  - 유튜브: 가장 안전(공식 예시+실사용 검증). **라이브는 유튜브 채널만** 받는 걸 기본으로.
  - 인스타그램: 내장 API 9종이 있어 성공 가능하나 에이전트가 웹을 직접 열면 로그인 벽 — **리허설에서 성공한 프롬프트 문구를 그대로 재사용**.
  - 틱톡: 전용 툴 없음 — **라이브 금지**, "틱톡 분석은 이메일로 보내드려요"로 우회.
- **플랜 B**: 분석 실패/지연 시 사전 캐시(`channel_profiles.csv` 가상 채널 5개 + `matched_recommendations.csv` 추천 결과)로 10초 내 전환. 제3자 장기 테스트 기준 자동화 실패율 15~20% 보고 — 플랜 B는 장식이 아니라 필수 장비다.

### 장면 4. 자동 갱신 (Test Run 함정 주의)

- 스케줄 워크플로우("매일 06:00 Korea time 트렌드 리서치→DB 갱신")를 실제로 걸어 두고, 무대에서는 **설정 화면 + 'Next Run At' + 실행 이력 패널**을 보여준다.
- **함정**: 워크플로우 **Test Run은 시뮬레이션이다 — 실제 메일도 안 나가고 데이터도 안 바뀐다**(공식 문서 명시). "지금 버튼 눌러서 새 행이 추가되는" 시연은 Test Run으로는 불가능. 라이브로 갱신을 보여주려면:
  - 방법 A: 데모 시각 직전에 발화하도록 **커스텀 간격(예: 30분마다) 스케줄을 타이밍 조정** — 목요일 리허설에서 발화 시각 정확도 검증 필수.
  - 방법 B(안전): 그날 아침 실제 실행된 이력 + 새로 추가된 행(수집일=오늘)을 보여주며 "오늘 새벽에 이 8건이 자동으로 들어왔습니다".
- "쇼츠만 보여줘" 즉석 수정은 장면 2의 검증된 패턴 그대로.

### 장면 5. 이메일 엔딩 — "지금 받은편지함을 열어보세요"

- 상시 운영: 30분 간격 워크플로우가 '대기' 리드를 배치 처리(분석→추천 저장→**Gmail 발송**→상태 '완료'). Gmail/Outlook 연동을 사전 완료해야 발송이 된다(미연동 시 실패, 공식 명시).
- **무대 클라이맥스**: 미리 섭외한 방문자(또는 스태프) 1명의 리드를 라이브로 처리하고, 그 사람이 폰으로 받은편지함을 여는 화면을 미러링 — 데모가 무대를 넘어 관객 주머니까지 도달하는 순간. 발송 소요 시간은 수요일에 실측해서, 길면 "접수하시면 5분 내 도착합니다" 멘트로 설계.
- 메일 내용: ① 맞춤 추천 리포트(추천 3건 + 첫 3초 훅) ② **'내 채널 트렌드 진단 에이전트' 공유 링크**(커스텀 슈퍼 에이전트 — 화요일 실검증 통과 시) 또는 빌드 프롬프트 레시피 전문. 발신은 데모 전용 Gmail(실계정 금지). **첫 발송분은 스팸함 분류율을 반드시 확인**.

## 3. 데모 2·3 — 임팩트 연출 반영

### 데모 2. 수출입 정리 시스템 — "3분 카운트다운 쇼"

- 대형 화면에 3:00 타이머. 시작 직전 **관객에게 즉석 요구사항 1개**를 받는다("환율 자동 계산 컬럼도 넣어주세요") — "사전 녹화가 아니라는 증거는 방금 그 요청입니다."
- `creator_trade_ledger.csv` 업로드 + 자연어 한 문장으로 빌드. 공식 퀵스타트 기준 "첫 시스템 10분 이내"이고 AI가 확인 질문을 먼저 던지므로, **3분은 '생성 시작~첫 테이블'까지**로 잡고 타이머 초과 시 사회자 멘트("에이전트도 야근을 하네요") + 사전 생성본 전환. 5회 이상 타임어택 리허설로 실측 후 타이머 시간을 확정한다.
- 생성 직후 AI가 샘플 데이터를 자동으로 채워 화면이 비지 않는다(공식 확인) — 데모 안전장치.
- 킬러 명령: "관세 납부 대기인 건만 보여줘"(필터형 — 공식 예시와 동일 유형), "이번 달 수출 원화 합계 알려줘".

### 데모 3. 협업 일정 관리 — 뷰 전환 + (옵션) 음성 피날레

- 칸반(단계별)/캘린더(마감일)/테이블 **원클릭 전환**이 메인 비주얼(즉각 반응·무료).
- "이번 주 마감인데 초안 단계인 프로젝트 보여줘" → "지연 건 담당 매니저에게 리마인드 메일 초안 써줘"(발송까지 하지 말고 **초안 검토 화면**에서 멈추는 게 실제 제품 흐름과 일치하고 안전).
- **옵션 피날레**: Speakly(공식: 한국어 포함 100+ 언어, Agent Mode로 음성→에이전트 작업)로 키보드 없이 "지연된 태스크만 보여줘"를 **말로** 시연. 화요일에 한국어 인식률 테스트 통과 시에만 채택, 실패 시 타이핑 폴백.

### 옵션. 여행 플래너 (AI Developer)

- Publish → 즉시 공개 URL은 검증됨(6개월 지난 배포 링크 생존 확인). 앱은 **사전 제작·다듬기**(첫 결과물 품질 편차 보고됨), 무대에서는 **Publish 클릭 → 청중 폰으로 접속**하는 순간만 라이브 — 실패 위험이 가장 낮은 라이브 장면이다.

### 행사 후 리드 전환 (옵션, 여력 시)

- AgentBase로 '행사 리드 CRM'(수집→리포트 발송→상담 제안 단계) 구성 — 이 CRM 대시보드 자체를 부스 서브 화면에 띄우면 "AgentBase가 지금 이 행사의 리드를 관리 중"이라는 4번째 데모가 된다.
- D+1 맞춤 리포트 / D+3 진단 에이전트 링크 / D+7 상담 제안의 3단 시퀀스를 스케줄 워크플로우로. 차별화 한 방: 상위 리드 10명에게 **AI Pods로 만든 '내 채널 전용 트렌드 브리핑 팟캐스트'(3~5분)**를 D+3 메일에 첨부 — 텍스트 리포트는 안 열어도 "내 채널 얘기하는 방송"은 연다.

## 6. 크레딧 예산 (검증된 수치 기반)

- 무료 플랜(일 100크레딧)으로는 **리허설 1회면 소진** — 라이브 데모 불가. **Plus(월 $24.99, 10,000크레딧)가 최소**, 부족 시 $20=10,000크레딧 팩 당일 충전 가능(3개월 유효).
- 실측 소모 감각: Super Agent 실행 ~100/회, AI Sheets 리포트 ~166, 슬라이드 145~450, 랜딩페이지 600~1,200. 리허설 3회+본번을 돌려도 Plus 잔량으로 충분하지만, **AgentBase 작업 자체의 크레딧 단가는 미공개** — 리허설 때 실행 전후 잔량을 기록해 본번 소모량을 추정할 것.
- 유료 플랜은 2026-12-31까지 AI 채팅·이미지 생성이 크레딧 0 — 시간 때우기용 가벼운 시연은 부담 없다.
- 집중 사용 시 약 5시간 단위 레이트리밋 보고 있음 — **리허설은 본번 최소 반나절 전 종료**.

## 8. 계정 수령 즉시 실검증 목록 (웹 문서로 확인 불가능했던 것)

우선순위순. 결과에 따라 대본이 갈린다.

1. **폼 제출 → 대시보드 반영 지연**: 실시간인가, 새로고침 필요한가, 몇 초 걸리나 (장면 3 하이라이트의 성패)
2. **공개 폼 모바일 UX**: 폰 렌더링, 제출 후 자동 리셋(연속 입력), 제출 횟수 제한 여부, **동의 체크박스 필드 지원 여부**
3. **30분 간격 스케줄 + "대기 상태만 처리" 배치 워크플로우**가 실제로 동작하고 중복 발송이 없는지
4. **한국어 프롬프트 품질**: 한국어 지시로 대시보드 생성·수정 시 필드명·라벨이 깨지지 않는지 (확인된 사례는 거의 전부 영어)
5. **커스텀 슈퍼 에이전트 공유 링크**: 비계정 사용 가능 설정, 파이프라인 패키징 품질
6. **AgentBase 작업별 크레딧 소모** 실측 (실행 전후 잔량 기록)
7. **동시 접속**: 태블릿 2대+노트북이 같은 워크스페이스에 동시 입력 시 충돌 여부
8. AgentBase 프리뷰가 데모 계정 플랜에서 활성화되는지 (웨이트리스트/플랜 제한 여부)
9. Gmail 연동 계정의 일일 발송 한도·스팸 분류율 (테스트 수신 계정 3곳: Gmail/네이버/카카오)
